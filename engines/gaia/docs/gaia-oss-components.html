方案设计关键事实

📊 体积分布
基础设施占绝对大头（minimal 3.3GB / full 8.6GB），自定义镜像仅 336MB。本地化瓶颈是基础设施镜像分发，不是 Gaia 代码。
🖥 ARM 兼容
全 arm64：Gravitino/Trino/Kafka/Neo4j/PG一体/RustFS/nginx/自定义。
❌ 仅 amd64：Doris FE+BE、SeaTunnel —— arm64 本地化硬障碍。
🚀 国内拉取
docker.io 直拉卡死（Trino 2.37GB 实测 19min 未完成）。docker.1ms.run 稳定（Trino 12s 下完）。建议预置 registry mirror 或离线 OCI tar（make package 已支持）。
💾 JVM 内存
Gravitino/Trino/Doris 都是 JVM，冷启动 30-90s，内存 1-3GB。8GB 机器跑 minimal 勉强，full 至少 16GB。
⚠️ 仓库不提交的坑
① config/trino/gravitino/ connector JAR 需下 GitHub release
② make docker-all 漏建 gaia-gravitino-libs
⚙️ colima k3s
docker+k3s profile 共享镜像 store，docker build/pull 即 k3s 可见，不需要 ctr import（README 的 import 步骤多余）。
