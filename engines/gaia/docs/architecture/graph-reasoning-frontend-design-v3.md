# 图探索前端体验简化设计 —— 从"控件堆砌"到"对话即探索"

> **状态**：设计定稿（待评审）
> **版本**：v3（2026-07-03）
> **前置**：[graph-reasoning-frontend-design-v2.md](./graph-reasoning-frontend-design-v2.md)（功能完整版，技术人可用）
> **核心矛盾**：v2 功能完整但首次进入门槛极高——顶栏 7 个控件 + 空画布"搜索对象开始探索"，最终用户无从下手

---

## 〇、问题诊断

### 当前首次进入体验（v2）

用户进 `/explore` 看到的：
```
[本体▼] [对象类型▼] [属性过滤] [加载对象] | [NL提问] [💬问] | [布局▼] [图谱/地图/分屏] [▶轨迹]
统计: 节点0 边0
┌─ 空画布 ────────────────────────────┐
│        🔍                            │
│     搜索对象开始探索                  │
└──────────────────────────────────────┘
[选中/图层/分布/探索] 选中节点查看详情
[时间轴：画布节点无时序数据]
```

**7 个下拉/按钮 + 4 个 tab + 空画布**。用户第一反应：我从哪开始？为什么有这么多控件？我该选什么？

### 痛点根因（对照调研）

| 痛点 | 根因 | 调研依据 |
|------|------|---------|
| 一次给太多控件 | 违反渐进式披露（progressive disclosure） | Nielsen Norman：show only what's needed now |
| 空画布只说"搜索对象" | 传统空状态在 AI 时代已失效 | "The death of empty state"：空状态应给 worked example + starting verb |
| 用户不知问什么 | 没有"起始动词"和"worked example" | Notion AI 空状态：3 个起始动词 + 6 个示例 |
| 选本体→选类型→加载 三步才能看到东西 | 没有上下文预填充 | Vertex：URL 参数带 objectSet/searchAround/timeRange 预填充 |
| NL 输入框占顶栏角落 | AI 不是主入口而是附属 | AI 分析平台趋势：对话即主交互，控件是辅助 |

## 一、设计原则（调研提炼）

### 1.1 三条核心原则

**原则 1：对话即探索（Conversational-first）**
> 不是"先选控件再探索"，而是"先说诉求，系统自动探索"。
- 主入口是中央对话框（不是顶栏角落的 NL 输入）
- 用户说"看看高风险供应商的关联订单" → 系统自动：选本体→过滤 riskLevel=high→加载→展开 supplies→着色
- 控件退为"微调"角色，对话后浮现

**原则 2：渐进式披露（Progressive Disclosure）**
> 首次进入只看到对话框 + 示例。探索开始后，相关控件才按需出现。
- 三层：Discover（看到能问什么）→ Understand（看到结果+关键控件）→ Execute（高级配置面板）
- 不一上来展示布局/视图/轨迹/分布 tab

**原则 3：worked example + 起始动词**
> 空状态不是"搜索对象开始探索"，而是给具体示例 + 动作动词。
- 起始动词："查看" "找出" "追踪" "分析"
- worked example："查看所有高风险供应商" "找出 S001 的关联订单" "追踪 48h 内的订单变化"

### 1.2 AI 空状态四属性（调研："death of empty state"）

| 属性 | 含义 | Gaia 应用 |
|------|------|----------|
| **worked example** | 给一个真实可点的示例 | "查看高风险供应商"（点击直接执行） |
| **starting verb** | 起始动词而非名词 | "查看/找出/追踪/分析" 而非"对象/关系" |
| **model knowledge** | 暴露系统知道什么 | "本本体有 Supplier/Order/Material，可探索 supplies/usedIn 关系" |
| **action affordance** | 明确可做什么 | 示例卡片可点击，不是只读提示 |

## 二、新交互设计

### 2.1 首次进入：对话式空状态

```
┌──────────────────────────────────────────────────┐
│                                                    │
│            🔍 图探索                              │
│        用自然语言探索你的业务网络                   │
│                                                    │
│   ┌──────────────────────────────────────────┐    │
│   │  问问看…（如：查看高风险供应商的关联订单）  │    │
│   │                                    [💬 探索] │    │
│   └──────────────────────────────────────────┘    │
│                                                    │
│   试试这些：                                       │
│   ┌─[查看所有供应商]─┐ ┌─[找出高风险供应商]─┐     │
│   ┌─[追踪近期订单]───┐ ┌─[分析供应链中断]───┐     │
│                                                    │
│   💡 当前本体 ChainSmoke 含 Supplier/Order/        │
│   Material，可探索 supplies / usedIn 关系          │
│                                                    │
└──────────────────────────────────────────────────┘
```

**关键**：
- 中央对话框是主入口（不是顶栏角落）
- 4 个示例卡片**可点击直接执行**（worked example + starting verb）
- 底部暴露本体结构（model knowledge），让用户知道能问什么
- **没有任何下拉/布局/视图控件**——首次进入零认知负担

### 2.2 探索中：对话 + 画布 + 上下文控件

用户点"找出高风险供应商"后，界面展开：

```
┌─顶栏（精简）──────────────────────────────────────┐
│ ChainSmoke ▼   [💬 新对话]           节点50 边104 │
├─对话流（左 320px）─┬─画布（主）──────────────────┤
│ 👤 找出高风险供应商 │                              │
│ 🤖 找到 8 个高风险   │      ◯──◯──◯                │
│ 供应商，已加载到画布 │     /│      │\               │
│ [查看 IR] [证据]    │    ◯  ◯──◯  ◯               │
│                     │     \│      │/               │
│ 👤 展开他们的订单    │      ◯──◯──◯                │
│ 🤖 已展开 supplies   │                              │
│ 关系，新增 32 订单   │                              │
│                     │                              │
│ ┌─问问看…─────┐    │  [布局▼] [图谱/地图]         │
│ │             │[💬] │                              │
│ └─────────────┘    │                              │
├────────────────────┴──────────────────────────────┤
│ 选中节点 → 右侧详情（悬停或点击展开）              │
└──────────────────────────────────────────────────┘
```

**关键变化**：
- 对话流在左侧常驻（不是顶栏一次性输入），多轮探索有上下文
- AI 回复包含**可执行的下一步建议**（"展开他们的订单"是 AI 建议的追问）
- 顶栏极简：只有本体切换 + 新对话 + 统计
- 布局/视图等控件**只在画布右上角**，按需点开（不占主视觉）
- 选中节点详情**悬停浮层**或点击右侧展开（不是常驻侧栏 tab）

### 2.3 对话驱动的自动编排（核心 AI 能力）

> **实现说明（2026-07-03）**：原始设计含「确认/调整步骤」环节，实际落地简化为直接执行（更轻量、减少打断）。确认环节作为后续增强。

用户一句"分析供应链中断" → LLM 自动拆成多步操作计划，前端逐步执行：

```
👤 分析供应链中断风险
🤖 我将执行：加载所有供应商，展开其供应的物料，按风险等级着色，并切换至地图视图...
   1. 加载所有供应商
   2. 展开供应商供应的物料
   3. 按风险等级着色供应商节点
   4. 切换至地图视图查看地理分布
   5. 完成提示
   
   ── 执行中 ──
   ✓ 加载所有供应商（50 个对象）
   ✓ 按风险等级着色供应商节点
   ✓ 展开供应商供应的材料
   ✓ 切换到地图视图查看供应商地理位置分布
   
   请关注红色高风险的供应商及其供应的关键材料...
```

**实现架构**（真 AI 编排，非硬编码模板）：
- 后端 `POST /objects/{ont}/explore-plan`：LLM 把问题拆成 `ExplorePlan`（steps[] 多步）
  - `explore_plan_parser` service 复用 object_set_parser 四层保障（prompt 标准化 + 输出清洗 + Pydantic 校验 + 纠错环）
  - 5 种步骤类型：load / search_around / switch_view / color_by / message
- 前端 `usePlanExecutor`：逐步执行，每步更新对话流 + 画布
- `runNLQuery` 智能路由：复杂分析类问题（分析/评估/排查/挖掘）走编排，简单查询走 queryNL+fallback

**这是 v3 的灵魂**：用户只说目标，AI 自动编排多步探索（调 queryDataFrame + searchAround + 着色 + 视图切换）。把"选类型→加载→右键→展开→着色"5 步压缩成 1 句话。

### 2.4 场景模板（一键预置探索）

> **实现说明（2026-07-03）**：模板不硬编码步骤，而是**预填对话问题走真 AI 编排**。这样 LLM 根据当前本体结构动态拆步骤，比硬编码更灵活。

ExploreLanding 提供 4 个场景模板入口（对齐 RelationalAI templates + Neo4j supply chain demo）：

```
┌─场景模板──────────────────┐
│ 📦 供应链中断分析   风险传导+地理分布  │ ← 预填「分析供应链中断风险」
│ 🔍 隐性关联挖掘     多跳关系+路径推理  │ ← 预填「挖掘对象间的隐性关联」
│ 🕐 时序异常排查     时间窗+状态过滤    │ ← 预填「排查近期的时序异常」
│ 🗺 地理分布查看     空间分布+框选过滤  │ ← 预填「查看对象的地理分布」
└─────────────────────────────────────────┘
```

点模板 = 预填对话问题 → 走 §2.3 的 AI 编排。用户不用从零组织语言，但 LLM 仍根据当前本体动态拆步骤（不是写死的 N 跳+着色）。

## 三、技术实现路径

### 3.1 对话式入口重构

**新组件**：`ExploreLanding`（空状态）+ `ConversationPanel`（对话流）

```
GraphExplorePage 状态机：
  mode: 'landing' | 'exploring'
  - landing: 显示 ExploreLanding（对话框 + 示例 + 本体知识）
  - exploring: 显示 ConversationPanel + GraphCanvas
```

**对话流数据结构**：
```typescript
interface ChatMessage {
  role: 'user' | 'assistant';
  content: string;
  /** AI 回复附带的操作（可点击执行下一步）*/
  suggestions?: Array<{ label: string; action: 'nl' | 'expand' | 'view'; payload: string }>;
  /** 关联的证据链/IR*/
  evidenceId?: string;
  ir?: ObjectSetIR;
}
```

### 3.2 AI 自动编排（后端扩展）

当前 `query_nl` 只返回单次对象集 IR。扩展为**多步编排**：

新端点 `POST /objects/{ont}/explore-plan`：
```json
{"question": "分析供应链中断风险"}
```
后端 LLM 产**操作计划**（ExplorePlan，多步）而非单次 IR：
```json
{
  "summary": "供应链中断分析",
  "steps": [
    { "type": "load", "description": "加载所有供应商", "payload": {"type":"objectType","object_type":"Supplier"} },
    { "type": "color_by", "description": "按风险着色", "payload": "riskLevel" },
    { "type": "search_around", "description": "展开供应关系", "payload": "supplies", "source": "first", "direction": "forward" },
    { "type": "switch_view", "description": "切到地图视图", "payload": "map" },
    { "type": "message", "description": "完成提示", "payload": "分析完成" }
  ]
}
```

实现：
- `core/schemas/explore_plan.py`：ExplorePlan + ExploreStep schema
- `services/textql/explore_plan_parser.py`：LLM 产计划，复用 object_set_parser 四层保障（prompt 标准化 + 输出清洗 + Pydantic 校验 + 纠错环 ≤2 次）
- 5 种步骤类型：load / search_around / switch_view / color_by / message
- 前端 `usePlanExecutor` hook 逐步执行，每步更新画布 + 对话流

### 3.3 场景模板（前端预置 + localStorage 自定义）

```typescript
const SCENARIO_TEMPLATES = [
  {
    id: 'supply-chain-risk',
    label: '📦 供应链中断分析',

```

### 3.4 URL 参数预填充（对齐 Vertex）

支持 `/explore/:ontology?objects=S001,S002&view=map&time=48h`，从其他页面带上下文进入图探索（如从对象详情页"在图中查看"按钮）。

## 四、分层用户适配

| 用户类型 | 首选入口 | 控件可见性 |
|---------|---------|-----------|
| **业务用户**（运营/管理） | 对话框 + 场景模板 | 默认隐藏高级控件 |
| **分析用户**（数据分析师） | 对话框 + 画布微调 | 画布右上角控件可展开 |
| **技术用户**（开发者） | 高级模式：完整 v2 界面 | 顶栏「⚙ 高级」切换回 v2 |

一个「⚙ 高级」开关，技术人切回完整控件，业务用户用对话。两全。

## 五、与现有 v2 的关系

v2 的所有功能**不丢弃**，而是重新组织呈现层级：

| v2 功能 | v3 呈现方式 |
|--------|------------|
| 顶栏本体/类型/过滤下拉 | 移到「⚙ 高级」模式；对话模式自动推断 |
| NL 输入框 | 升级为中央对话流（多轮） |
| GraphCanvas | 保留，主视觉 |
| 侧栏 4 tab | 选中节点时浮层展开，非常驻 |
| SearchAroundConfigPanel | AI 自动编排替代手动配置；高级模式保留 |
| MapPanel/TimeScrubber | AI 编排自动切换；高级模式手动 |
| EvidenceDrawer | 对话流里"查看证据"链接 |
| PathFinder | 对话里"找出 X 和 Y 的路径" |
| Action 闭环 | 对话里"标记风险"建议 + 节点右键 |

**v3 不是重写，是 v2 的"对话优先"皮肤**。
