# 接口契约（A 团队 W1 冻结，B/C 据此 mock）

> 本文档是三团队并行的对齐基线。A 团队在 W1 必须冻结以下契约并以此实现；B/C 团队在 A 落地前按本契约 mock 联调。
> 任何字段/路径变更必须先改本文档并通知 B/C。来源：Repo2 V3 实现 + Repo1 adapter 机制。

## 1. DNS 命名规范（跨 A/B 约定）

引擎 Pod Service DNS（Gateway 与 Controller worker 共同遵守，无运行时依赖）：

```
engine-{engine_type}-{instance_id[:8]}.{namespace}.svc.cluster.local
```

| engine_type | 端口 | 说明 |
|---|---|---|
| `hermes` | 8642 | OpenAI 兼容，多 Profile |
| `openclaw` | 8642 | OpenAI 兼容 |
| `dify` | 8080 | 原生 Dify API，需 adapter 协议转换 |

- 请求头 `X-Agent-ID` 携带 instance_id；`X-Engine-Type` 携带 engine_type。
- Dify 的 short_id 取 `agent_id.replace("-","")[:8]`（与 Repo1 `DifyAdapter._build_url` 一致）。
- Profile 感知路由（Repo2 F-GW-002）：Profile 名 `{short_agent}-{scope_hash[:6]}-{short_user}`，INDEPENDENT/SHARED 两种，60s 正缓存 + 10s 负缓存。
- **现状提示（B 落地注意）**：Repo2 现仅 hermes 写死 `engine-hermes-{short_id}` 及 scope 变体 `engine-hermes-{id[:8]}-{scope_hash[:6]}`（`services/gateway/app/{lifecycle,proxy}.py`、`profile_resolver.py`），端口 `settings.engine_port=8642`。dify/openclaw 命名来自 Repo1 adapter。B 需把 `build_engine_url` 从 hermes 写死泛化为 engine_type 驱动。

## 3. Worker 生命周期 API（A 实现，B gateway + C 前端消费）

前缀 `/api/controller`（controller 并入 manager 后由 manager 挂载，路径不变）。统一 `ControllerError`。

- `POST /api/controller/agents/{agent_id}/deploy` — F-CTL-001
- `GET  /api/controller/agents/{agent_id}/status` — F-CTL-002
- `POST /api/controller/agents/{agent_id}/{suspend|resume|destroy|restart}` — F-CTL-003~006
- `GET  /api/controller/agents/{agent_id}/deploy/events` — F-CTL-007（SSE）
  - **事件 schema（已冻结）**：SSE 行 `event: progress`，`data` 为 JSON `{step, message, percentage, engine_url}`。
    - `step`：`starting`(10) / `creating_pod`(30) / `configuring`(50) / `waiting_ready`(70) / `validating`(80,90) / `engine_ready`(100，终态完成) / `error`（终态失败）。
    - `percentage`：0-100 整体进度（注意是 `percentage`，非 `progress`）。
    - `engine_url`：引擎就绪后回填，其余为 null。
    - 流在 `step ∈ {engine_ready, error}` 后终止。前端 `engine_ready`→完成、`error`→失败。
    - manager 代理路径 `GET /api/manager/agent-instances/{id}/deploy/events`（query token 鉴权，EventSource 不支持 header）原样透传同一事件流。
- `POST /api/controller/agents/{agent_id}/config/{sync|apply}` — F-CTL-040
- `POST /api/controller/agents/{agent_id}/persona/sync` — F-CTL-042
- `POST /api/controller/agents/{agent_id}/skills/install`、`DELETE .../skills/{skill_name}`、`POST .../skills/config/sync`、`GET .../skills/list` — F-CTL-043
- `GET  /api/controller/agents/{agent_id}/models` — F-CTL-060（按虚拟 Key 返回可用模型）
- `POST /api/controller/profiles`、`.../profiles/ensure`、`DELETE .../profiles/{profile_id}`、`POST .../profiles/register` — F-CTL-020,024
- `GET /api/controller/engine-instances/{instance_id}/pods`、`.../pods/{pod_name}/logs`、`.../pods/metrics` — 实例运行时详情
- `GET /api/controller/chat/{dashboard/config|dashboard/status|settings|models}` — F-CTL-061（前端探活）

## 4. Gateway 对终端 API（B 实现，C 消费）

前缀 `/api/gateway`。头：`X-Agent-ID`、`X-Engine-Type`、`X-Session-ID`。JWT 认证。

**实现提示**：Repo2 现状下 `/v1/*` 无显式路由，全部走 catch-all `@app.api_route("/{path:path}")` + `proxy.py` 转发；B1 引入 adapter 后会改为显式路由（参考 Repo1 `controller/main.py` 的 `/v1/chat/completions`、`/v1/models`、`/v1/sessions`、`/v1/files`、catch-all）。下列为客户端可见路径（nginx 剥离 `/api/gateway/` 前缀后到达 gateway）：

- `POST /api/gateway/v1/chat/completions` — SSE 流式（F-GW-010；adapter 按 engine_type 转协议）
- `GET  /api/gateway/v1/models` — 动态模型加载（F-END-050）
- `POST/GET/PATCH/DELETE /api/gateway/v1/sessions`、`GET .../sessions/{id}/messages` — 会话（F-GW-041；引擎托管优先、SQLite 兜底）
- `GET /api/gateway/v1/files` — 文件浏览器（F-END-030）
- IM 回调：`POST/GET /api/gateway/channel/{channel_type}/{agent_id}/callback` — F-GW-022~024（`channel_type` ∈ feishu/wecom/dingtalk；Repo2 `channel/router.py`，前缀 `/api/gateway/channel`）
- `GET /api/gateway/health` — F-GW-052

adapter 协议转换契约（Repo1 机制）：
- `EngineAdapter` 接口：`build_upstream_url` / `transform_headers`（去 Origin/Referer + 换引擎 key + 会话头翻译）/ `transform_request_body` / `transform_response_body`(SSE) / session+files URL 钩子。
- DifyAdapter 路径映射：`chat/completions`→`chat-messages`、`sessions`→`conversations`、`models`→`parameters`；SSE `event:message/message_end`→OpenAI `chat.completion.chunk`+[DONE]。

## 5. Hub API（B 实现，C 消费）

前缀 `/api/hub`。独立 DB（hub 自管 alembic）。组隔离（hub_item.group_id）。端口 8003。

- hub_item CRUD + 版本（hub_item_version）+ 关系（hub_item_relation）+ 标签（tag/hub_item_tag）
- 审批：approval_record
- 安全扫描：scan_report / scan_finding
- 生命周期事件：lifecycle_event
- 生命周期：Import → Review → Publish → Discover（Repo1 SERVICE.md 已验证核心链路）
- `GET /api/hub/health` — **已存在**（Repo1 `api/health.py`，返回 `{"status":"ok"}`；SERVICE.md "未实现" 描述已过时）

## 6. nginx 路由（C/部署对齐）

```
/api/manager/    → manager:8002
/api/controller/ → manager:8002   # controller 已并入 manager
/api/gateway/    → gateway:8010   # 剥离前缀
/api/hub/        → hub:8003
```
SSE 长连接 `proxy_buffering off`；不设 `Connection upgrade`。
