# 融合项目启动指南（三团队 Claude Code 并行）

## 一、下发方式

任务书已全部在仓库 `docs/merge/`，Claude Code 可直接读取，**不需要外部文档**。下发 = 克隆仓库 + 跑 kickoff 提示词。

```
docs/merge/
├── 00-融合总览.md            # 全局背景与决策（全员先读）
├── 01-接口契约.md            # 冻结的接口契约（A 维护，B/C 据此 mock）
├── team-A-后端核心.md
├── team-B-网关渠道Dify-hub.md
├── team-C-双前端.md
└── 启动指南.md               # 本文件
```

## 二、关键：先做「基座落地」（顺序前置），再三团队并行

三团队都依赖 Repo2 V3 基座已在 `develop` 上就位。所以**不能直接三团队同时裸启动**，需分两步：

### Step 0（一次性，顺序）— 基座落地
由一人（或 A 团队 Day1）在 `develop` 上完成：
1. 从 Repo2(`/Users/friday/Projects/union-agents`) 拷入：`services/{manager,controller,gateway}`、`apps/{admin,enduser}`、`pkg/`、`scripts/`、`deploy/`
2. 移除 Repo1 V1 残留：`services/manager`(V1)、`services/controller`(V1)、`services/llm-gateway`、`services/channel-gateway`
3. **保留** Repo1 的 `services/hub/`（B 团队 B8 接入）
4. 验证：manager/gateway 可启、`/health` 200、seed 幂等
5. 合入 `develop`，打 tag `merge-base-v3`

> 这一步是所有团队的起跑线。未完成前 B/C 无法启动（没有 Repo2 代码可改）。

### Step 1（并行）— 三团队分支
基座落地后，三团队各自拉分支并行：
```
git checkout -b feat/merge-A origin/develop   # A 后端
git checkout -b feat/merge-B origin/develop   # B 网关/渠道/Dify/hub
git checkout -b feat/merge-C origin/develop   # C 双前端
```

## 三、目录隔离（避免并行冲突）

| 团队 | 主目录 | 共享/需协调 |
|---|---|---|
| A | `services/manager/`（含 controller→worker 并入）、`scripts/`、`pkg/`、`deploy/k8s/services/manager*` | `pkg/`(共享模型)、`deploy/k8s/`(B 也改 hub/nginx) |
| B | `services/gateway/`、`services/hub/`、`deploy/k8s/services/{gateway,hub}*`、nginx 配置 | `deploy/k8s/`、`docs/merge/01-接口契约.md`(只读) |
| C | `apps/admin/`、`apps/enduser/` | 几乎无冲突 |

冲突点仅 `pkg/`(A 改共享模型) 与 `deploy/k8s/`(A/B 都加 manifests)。约定：`pkg/` 变更由 A 统一走 develop，B/C 频繁 `git pull origin develop`；`deploy/k8s/` 各加各的文件不互改。

## 四、契约变更协议

`01-接口契约.md` 是三团队对齐基线：
- **A 拥有写权**，W1 冻结后任何字段/路径变更必须：① 改契约文档 → ② commit 到 develop → ③ 在群里通知 B/C。
- B/C 把 develop 的契约变更合入自己分支（`git pull origin develop` 或 rebase），同步更新 mock。
- B/C 发现契约不够用，向 A 提需求，由 A 改契约，不擅改。

## 五、集成顺序（W5~6）

按依赖合入 develop：**A 先合 → B 再合 → C 最后合**（A 提供真实 API 后 B 切真实、B 提供真实 gateway/hub API 后 C 切真实）。每步合并跑 `00-融合总览.md` 的验证清单。

## 七、协作约定

- 每个团队 Claude Code 首条消息即上述 kickoff 提示词；之后正常对话推进。
- 三团队共享一个群，契约变更、阻塞、联调节点在群里同步。
- `develop` 是集成分支，feat/merge-* 分支定期 rebase develop。
- Repo2 路径若团队不在本机，需先把 Repo2 拷到各团队机器对应路径，或打包成只读归档。
