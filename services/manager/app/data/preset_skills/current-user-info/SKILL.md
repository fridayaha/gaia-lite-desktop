# 当前用户信息查询

## 概述

处理任务需要当前用户的基本信息时，通过 `terminal` 工具执行 `get_user_info.py`，
向平台查询该用户的最新资料（用户名、真实姓名、邮箱、手机号、角色、用户组、
业务身份等）。每次调用都返回数据库最新值，**不要依赖对话记忆中的用户信息**
（可能已变更）。

## 调用方式

**直接用 `terminal` 工具执行下面这条命令**（`find` 自动定位脚本，无需参数；
当前用户身份由脚本从运行环境自动识别，不要询问）：

```
python3 $(find /opt/data/skills -path "*current-user-info/scripts/get_user_info.py" -type f | head -1)
```

> ⚠️ **直接执行这一条命令即可，不要：** 读 config.yaml、修改 SKILL.md 或脚本、
> 询问用户身份/鉴权信息、用 `{{profile_skills_dir}}` 字面量（不会被替换，用上面的
> `find` 命令定位脚本）。

## 输出

脚本成功时 stdout 输出 JSON，退出码 0。形如：

```json
{"fields": {"用户名": "liuwei", "真实姓名": "刘伟", "手机号": "138****1234", "角色": "销售"}, "business": {"业务用户名": "LiuWei"}}
```

- `fields`：平台用户基本信息（用户名/真实姓名/邮箱/手机号/角色/用户组）。
- `business`：业务系统身份（业务用户名/手机号/邮箱，可能为空）。

未找到用户或查询失败时退出码非 0，stderr 输出错误提示。

## 何时调用

- **用户主动询问自身信息**：「我的手机号/邮箱/用户名/业务手机号是什么」「我是谁」
  「我的角色/身份/账号信息」等。**无论系统上下文是否已注入过类似数据，都必须调用
  本技能获取最新**——上下文与记忆（含 memory 工具记录）可能过期，例如业务手机号
  可能已在管理侧变更。
- **其他技能需要当前用户身份**：test-drive-report / customer-profile-update 等技能
  需要用户身份信息时，先调本技能获取最新，再作为参数传入下游技能，**不依赖上下文
  或记忆中的用户信息**。
- 任务需要按当前用户身份个性化处理（如按角色给出不同指引、按业务身份关联数据）。

## 注意事项

1. **不要凭记忆/上下文回答用户自身信息**：对话历史、memory 工具记录、系统上下文
   注入的用户信息**都可能过期**（用户可能在管理侧改了手机号/邮箱/角色）。涉及用户
   自身信息时一律调用本技能获取数据库最新值。
2. **本技能只读**：仅查询，不能修改用户信息。用户要修改资料（改手机号/邮箱等），
   引导其到用户中心或联系管理员，不要在对话中直接改。
3. **无需询问鉴权信息**：脚本从运行环境自动读取，属平台配置。
4. **退出码**：0 成功；1 环境缺失；2 平台返回错误；3 网络错误。失败时读 stderr
   提示用户稍后重试或联系管理员。
