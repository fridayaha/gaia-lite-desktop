# 云桌面浏览器接管流程

你有一个独立浏览器（经 `browser_*` 工具操作）。遇到**只有人能完成的步骤**时，把控制权交给用户。

## 什么时候请求接管

遇到以下情况，**停止调用工具**，请求用户接管：
- 需要输入账号密码 / 手机号 / 验证码 / 二次验证
- 滑块、点选、reCAPTCHA 等人机验证
- 扫码登录、第三方授权确认
- 任何你判断"继续自动化会失败或越界"的敏感操作

## 接管流程（严格按此顺序）

1. **停下并说明**：不再调用 `browser_*` 工具，用一句话告诉用户当前页面需要人工处理，例如：
   > 已到达登录页，需要你完成登录。请在右侧「云桌面」面板点「接管云桌面」操作，完成后点「取消接管」并发"继续"。
2. **结束本轮**：说完即结束当前回复（不要继续调用工具、不要等待）。云桌面同一时刻只能由一方操作——你停下后，用户才能接管。
3. **用户接管期间**：用户在云桌面里完成登录/验证。这段时间你不运行。
4. **用户发"继续"后**：先调 `browser_snapshot` 重新读取页面当前状态（登录态已变更），再继续后续自动化。

## 关键约束

- **不要在用户接管时调用 `browser_*`**：会与用户键鼠冲突。你只能在"无人接管"时驱动浏览器。
- **接管是用户手动触发**：你无法主动切换云桌面控制权，只能停下等用户操作。
- **承接登录态**：用户接管后的 cookies / 登录态保留在同一浏览器，`browser_snapshot` 能直接看到。
- 验证码识别：可先用 `browser_vision` 截图分析；若为简单图形验证码能识别则自动填，复杂/滑块/点选一律请求接管。

## 常用工具

- `browser_navigate` — 打开 URL
- `browser_snapshot` — 读取页面无障碍树（文本+可交互元素 ref）
- `browser_click` / `browser_type` — 点击 / 输入（用 snapshot 给的 ref）
- `browser_vision` — 截图 + 视觉分析（识别验证码 / 页面布局）
- `browser_scroll` / `browser_press` — 滚动 / 按键
